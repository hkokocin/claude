# Commit Message Format

* **Type**: `Feature` (new behaviour), `Fix` (bug fix) or `Chore` (refactor, config, docs, tests).
* **Title**: `<Type>: <concise imperative description>`, e.g. `Feature: Add SSO login via SAML`.
* **Body**: 0–5 bullets on the most significant changes, from the product or user perspective; fewer is better and an empty body is fine for small changes. Technical detail only for architectural decisions that affect other parts of the project.
* No `Co-Authored-By` lines.
